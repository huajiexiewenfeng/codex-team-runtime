# 固件升级团队案例：从任务拆分到可审查交付

> 脱敏的真实协作复盘；不包含成员身份、内部地址、凭据、任务链接、提交哈希或原始对话。
>
> 本文展示 Runtime 的使用方式，不把案例描述为 Runtime 功能的完备验证或产品端到端验收。

这个案例把浏览器侧 MQTT 升级进度处理迁入平台：前端通过 HTTP 操作和查询；平台保存任务、设备回包、进度和事件日志；在线与离线固件在准备完成后复用同一任务与命令通道。

代码交付已经过独立审查，但测试环境部署、外部版本配置与飞控/通信的四条真实设备升级路径仍待验证。**本地测试、HTTP 接纳、代码合入和设备升级成功是不同事实。**

## 角色、知识与项目边界

| 能力或角色 | 本案例中的职责 | 不负责什么 |
| --- | --- | --- |
| Manager | 范围核对、拆分派工、接口契约、独立审查和验收 | 不把 Worker 自报完成当作批准 |
| Liaison | 解释已记录进展与阻塞 | 不指挥 Worker、不改写 Manager 状态 |
| 前端 Worker | 页面入口、普通上传、HTTP 轮询、进度与日志展示 | 不自行解释设备进度或替换在线包元数据 |
| 平台 Worker | 任务、权限、回包解析、进度日志、在线候选与回执 | 不把回执重试变成再次安装 |
| 下游 Worker | 文件准备、持久幂等、命令发布与旧入口兼容 | 不承担平台任务状态机 |
| PDC / Base Graph | 定位候选上下游与已有能力 | 不替代当前源码、Git 基线和需求核实 |

按项目所有权分配 Worker，避免多个成员同时修改同一套任务持久化和状态代码。Graph 给出候选关系后，仍需回到需求、源码和当前分支确认“要改”“只读参考”和“外部负责”的边界。

## 推荐过程

1. **建立最小团队。** 核实 Manager、Liaison 与首个 Worker 的真实绑定；创建、注册、准备就绪和业务派工分开记录。
2. **先做 Task 0。** 三个项目分别核对入口、包装、字段、旧上传副作用、回包链路与可验证边界，再冻结跨项目契约。
3. **契约后并行实现。** 在线与离线只在固件元数据来源不同；准备后共用任务、日志、进度和命令，不新建两套状态机。
4. **独立审查提交。** 区分派工、发送、Worker 提交、Manager 接收、批准/返工、合入、部署和实机验证。
5. **用证据收口。** 真实设备、外部产品映射、可信离线版本来源与环境配置缺失时保留待验证项，不用 mock 或页面状态替代。

## 三次可复用的评审结论

### HTTP ACCEPTED 不能覆盖设备已知状态

设备回包可能先于 HTTP 接纳到达。较晚的 ACCEPTED 不能覆盖设备已上报的失败或新阶段；应答只能更新它能证明的事实，并以交错到达用例复审。

### 无影筝回执不等于再次安装

接受、成功、失败回执应有独立持久状态与迟到保护。回执失败重试只调用外部版本服务；不能重新下发设备升级命令，也不能让迟到响应改写已收敛的最终结果。

### 风险审查也会产生过度设计

曾为固件路径增加专用鉴权链路。经用户确认既有网关、SDK 与租户边界足够后，相关专用实现被删除。风险应先与系统既有边界和用户接受的部署方式核实；Manager 对自己批准的复杂度负责。

## 用统一工作台展示，不伪造指标

| 页签 | 数据 | 正确解释 |
| --- | --- | --- |
| 任务进度 | state 与 Registry 投影中的成员、任务、阶段、阻塞、提交和验收 | 页面刷新不代表 Worker 有新业务进展 |
| 指标统计 | 显式绑定的同团队 Metrics 日报：每日 Token 与 MCP observation | 没有日报或 observation 时必须显示未知，不能填 0 |

Token 日报应写明日期范围、时区、`asOf`、成员范围、来源、去重规则与缺失记录。团队、角色、成员和任务是同一批记录的不同视角，不能相加成新的总数。

MCP 统计只计入显式导入、名称精确匹配的直接 Team Context 观察。封装在其他工具中的调用可能不可见；“未观测到”不等于零调用，也不能推导角色召回率、后续行为或成本节省。

```text
node src/cli.mjs metrics-daily-export <state.json> <ledger.json> <daily-options.json> <new-daily-report-dir>
node src/cli.mjs dashboard-serve <state.json> --port 0 --metrics-report <new-daily-report-dir>/report.json
```

实际路径、日志和启动链接属于私有运行资料，不能提交到仓库。工作台仅做本机只读展示：不派工、不唤醒 Agent、不写业务状态，也不自动采集 Token。

## 验收清单

- [ ] 每个项目的实际差异、受影响测试、构建结果和提交/目标分支已由 Manager 独立核对。
- [ ] 已确认迁移、配置、认证、存储和消息订阅边界，使用已核实构建包部署。
- [ ] 已确认在线产品映射、身份规则、凭据安全注入和可信离线目标版本来源。
- [ ] 已分别验证飞控在线/离线、通信在线/离线，并记录任务标识、目标版本、结果和版本读回。
- [ ] 已覆盖重复提交、并发、断连、重启、迟到回包与回执重试，证明不会重复安装。

只有这些实际结果回填后，才能宣布端到端产品验收完成。
