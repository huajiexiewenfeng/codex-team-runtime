## 本轮基线与事实

样本 B0：2026-09-18 单服务本地打包 `live-play-package`。Manager Astra/medium、Worker Sol/medium。请求到最终交付约 55 分 53 秒；构建程序约 8 分 04 秒；正式 Worker 接到派发前有约 24 分钟历时；期间 Manager 有一次压缩。以上是单样本观察，不是普遍平均值。

发现：同次完成有两条 Manager 消息；通知后 Worker 反向等待 4 次，工具报告的等待时长合计 151.340 秒；正常通知流程需要多次 Agent 手工组织请求；Manager 多次步骤间隔为分钟级，内部命令通常为秒级。

限制：不能把所有空档都解释成模型推理；不能证明两条消息造成了 Manager 的长延迟；不能用该样本预测所有编码/测试任务；历史实际加载的规则版本未完全证实。

安装时间核对：低成本交付提示的本地安装清单时间为 9 月 18 日 14:14:40；禁止 Manager 临时子代理规则为 17:02:57，晚于本次交付，后者不能解释本次耗时。安装到磁盘不等于所有活跃任务当时已重新读取。

## 实验纪律

2026-09-22 测量工具记录（不是行为实验）：首版 `task-eval` 已对 B0 的 v3 时间线执行只读评估，生成 3 项声明阶段、3 项相邻日志间隔待复核卡。较长声明阶段为 executing 1501.979s、submitted 731.811s、reviewing 225.898s；这些值不是纯计算或可节省时间。63 项时间线/评估/工作台相关测试通过。仍无可比试用样本、无节省结论；`activeExperiment = none`。未安装、未改变通知/派工/验收规则。候选卡只是人工评估框架，下一步复核根因和反例，不以排序直接决定修改。

1. 每次只设一个 activeExperiment。测量上线 M1/M2 单独记录为测量版本，不同时改变业务路径。
2. 激活前保存实际安装文件哈希、Runtime commit 与 dirty 补丁标识、Skill/MCP 加载或重启证据、模型/强度、构建/测试命令和验收标准。当前版本不能冒充历史执行版本。
3. 实验窗口不顺带改模型、并发数、缓存策略、通知文案以外的工作流或验证标准；不可避免的变更标为混杂，样本保留但不作单因素结论。
4. 观察 1–2 天作为首次检查点，并以至少 3 个可比任务作为初步判断；未获得足够样本就延长观察而非宣布成功。跨任务类型分组，不强求对不同任务凑平均数。
5. 固定比较口径：同任务类型/范围、模型、验收要求、数据覆盖；同时报告 n、逐样本值、中位数与范围。小样本不宣传显著性或可靠 P95。
6. 同时观察主指标、端到端历时、已观测 Token 和质量护栏。不把 Worker 更早结束误报为用户更早拿到产物。
7. 角色漂移、漏报、重复执行、忙 Worker 被抢占、错误验收、证据丢失或权限绕过均属回退/停止条件。失败样本不能从对比表删除。
8. 仅更新实验指定的规则或接口；回退只还原该差异，不覆盖其他任务修改、已有产物、Registry 或业务记录。回退前检查是否已有依赖新格式的在途工作。
9. 保留历史实验行和证据，不把失败记录改写为成功。试用完成、用户确认后再按既定方式提交推送，不自动定时唤醒 Agent。

## 每次实验更新模板

复制以下字段追加到历史，不覆盖旧结果：

- 实验 ID、状态（候选/激活/观察/保留/调整/回退）、开始与结束时刻。
- 本次唯一改动、代码/Skill/安装哈希、实际生效证据、回退定位。
- 基线样本 ID、实验样本 ID、可比条件、混杂因素、未覆盖数据。
- 主指标逐样本值/中位数/范围；端到端、Token、质量护栏。
- 结论：证据支持什么、不支持什么；是否继续观察；由谁确认下一项。

**禁止**：只写“感觉变快”“应该节省了”；无证据填 0；删掉慢样本；同时开启第二个实验；把同一段并行时间或嵌套工具时长重复相加。
