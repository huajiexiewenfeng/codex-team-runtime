# Watchdog 宿主接入：隔离验证结果

日期：2026-11-16。状态：当前宿主受控验证完成；不是安装、生产安全保证或完整 P0 验收。未修改 Runtime、Skill、allowlist、宿主配置或业务团队状态，未合并。

版本补核：发送用 CLI `--version` 是 `0.167.0-alpha.4.1`，隔离聊天 `session_meta.cli_version` 是 `0.169.0-alpha.11.1`（source=vscode）。前者仅是队列客户端，不能当作执行宿主版本。本文结果限定于该客户端与原生日志版本组合；日志声明也不代替宿主二进制认证。

## 范围和方式

用户授权创建一个独立 Desktop 聊天。当前精确 CLI 为 0.167.0-alpha.4.1，使用官方 `codex queue --thread ... --message ...`，不使用 resume、daemon 或普通 steer 消息兜底。只向该隔离聊天发送测试消息；未联系三个业务团队。

共六个原生轮次：初始化、空闲提醒、45秒等待任务、忙碌期间排队的提醒、两轮相同正文提醒。初始化与提醒仅要求短答；等待任务只运行一次本机等待命令。没有业务开发或持续定时器。

原生 `wait_threads` 和 `read_thread` 核对目标身份、轮次、状态、实际用户消息和完成记录；额外只读该隔离聊天的精确日志文件。未把模型的 ACK 当作唯一执行证据，不读取模型推理正文。

## 结果

| 测试 | 实测 | 结论边界 |
| --- | --- | --- |
| 已加载、空闲入队 | CLI 返回队列 ID，随后独立新轮次正常完成 | 已证明本次当前版本空闲路径可用，不代表所有宿主状态 |
| 已加载、执行中入队 | 发送前后原 turnId 相同，均为 inProgress；原轮次正常完成后提醒才进入另一轮 | 本次未打断、未插入原轮次；不证明所有并发竞态 |
| 忙碌任务结束与提醒开始 | 原轮次耗时66.053秒，其中等待命令46.554秒；提醒轮次在前一轮结束后158毫秒开始 | 时间来自原生日志，不把模型耗时算成固定队列延迟 |
| 相同正文重复入队 | 两个队列 ID，产生两个不同且完成的 turnId | 宿主不按正文自动去重；Runtime 必须持久化去重 |
| 任务与执行关联 | 精确已发送正文可与原生 user-message 的 turn_id 元数据匹配，开始/结束事件交叉一致 | 受控测试可关联；不是生产认证或通用绑定接口 |
| 原执行与提醒分离 | 提醒正文引用原 execution，但自身拥有另一个 turnId | 不能把最新轮次完成当作原业务执行完成 |
| 重复与旧任务的反例 | 相同正文匹配两轮，判 unknown；未发送旧标记匹配零轮，判 unknown | 不按“最新一个”或时间最近强行归因 |
| 队列 ID 到轮次 | 此次 CLI queue ID 未出现在该聊天原生日志，turn_trigger 只标明 queue | 尚无直接 queueId→turnId 关联证据，不能把入队成功当作消费完成 |

## 对候选的结论

1. 当前版本已加载 idle/busy 的安全排队路径有新的实际证据，不能再一概说没有任何真实验证。
2. 生产 allowlist 仍保持空。此次调用的是官方 CLI 隔离实验，并非候选 Watchdog 全链路投递；没有绕过候选门槛。
3. 提醒和任务关联必须区分 execution turn 与 reminder turn。只靠 task_id/execution_id 文本或 ACK 不足以证明身份；同正文多次执行必须拒绝唯一归因。
4. 本机日志提供了一条可研究的只读关联路径，但依赖当前构建的日志结构，并非稳定公开 API。生产适配需要验证唯一发送记录、完整正文摘要、精确线程、用户消息来源、当前执行版本和原生轮次；不新增 Worker 恢复调用。
5. 本轮没有实现生产绑定或确认回执，也没有把受控消息写入业务台账。当前仍不满足完整 P0 安装标准。
