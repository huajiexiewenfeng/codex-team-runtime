# 最新工作台与历史快照

`dashboard-serve` 提供本机只读的统一团队工作台：「任务进度 / 指标统计」两个页签共享一个入口。任务随台账更新，指标按需读取显式绑定的日报快照。详见 [统一入口与数据边界](dashboard-portal.md)。`dashboard` / `snapshot` / `render` 继续导出不可变离线历史，不互相覆盖。

## 谁维护什么

| 责任方 | 责任 | 不做什么 |
| --- | --- | --- |
| Manager | 按既有权限登记团队、分配任务、记录审查与验收；确保进展、阻塞、提交进入正式台账 | 不为了刷页面编造进展，不把 Worker final 当验收 |
| Worker | 在自己的任务范围记录真实观察、提交证据，并按通知契约告知 Manager | 不接受页面分派、不代 Manager 验收 |
| Liaison | 读取、解释证据；在用户请求工作台时启动或复用已核实的只读服务入口 | 不写 Manager 状态、不为更新 HTML 唤醒 Agent |
| Runtime + 浏览器 | 读取当前 Node 状态及 Registry 投影，确定性渲染；页面可见时自动检查 | 不采集原生思维过程、模型计算状态或 Token；不执行任何业务写入 |

链路是「授权事件写入台账 → 浏览器请求 Runtime → 校验并读取记录 → 更新视图」。没有 Agent 为 HTML 值班；如果台账未写入进展，自动刷新也无法知道进展。页面分别标示最近成功核对时间、源更新时间、Registry 版本、业务观察时间及陈旧性；同步成功不等于业务刚有进展。

## 启动与停止

在可信 Runtime checkout 中，用原团队的权威状态路径：

```text
node src/cli.mjs dashboard-serve <state.json> [--port <0..65535>] [--codex-links] [--metrics-report <report.json>]
```

- 只绑定 `127.0.0.1`。默认端口 `4319`；多团队使用各自明确端口，或 `--port 0` 分配空闲端口。端口占用会失败，不抢占旧服务，也不静默切换团队。
- schema 2 需要本次进程的 `CODEX_TEAM_CONTEXT_PYTHON` 指向可信、匹配版本的 Python 环境，按既有 Registry 读取配置设置；不改变全局环境。读取错误不能绕过为旧 schema 1 缓存。
- 命令在前台运行，返回完整启动链接。保留此链接供同一运行实例复用，无需每次生成新的 HTML 目录。链接包含访问凭据，不能提交到 Git、公开分享或写进截图。
- 浏览器加载后清除地址栏凭据，并在该标签页的会话存储中复用；新标签页或其他浏览器需使用原始完整启动链接，不能只复制清除凭据后的地址栏。禁用会话存储时当次仍可用，重载需要完整链接。
- `Ctrl+C` 停止本次服务；没有自启、系统服务、自动续期或 MCP 全局注册。若启动进程被宿主结束，页面显示无法同步。服务重启生成新凭据，需要新的完整链接；不承诺跨重启 URL 永久有效。
- 重复打开时先核对已有启动记录中的 Runtime、state 路径与运行进程；只有能确认同一团队、同一运行实例才复用。不要根据端口、窗口标题或旧 HTML 猜测团队，也不要终止他人的进程。

页面每次请求**完成后**约 5 秒再次检查，不并发轮询。隐藏、暂停、关闭页面时停止发起请求；已开始的本地读取可能完成。暂停时仍可“立即刷新”，恢复或重新显示页面后继续；普通失败退避至最多 60 秒，凭据失败停止自动重试。暂停/断连不清空已有内容，也不把上一次成功数据冒充最新。

服务不设置扫描计时器、文件 watcher 或 Agent heartbeat；无页面请求时不读取台账。并发标签页合并正在进行的读取，成功结果最多缓存 1 秒。分钟级计时变化可能重算视图，但没有 LLM 消耗；本地文件读取、Python 投影及浏览器渲染仍有普通计算开销。

任务完成、轮次关闭或 Manager 暂时闲置不会退出角色，也不会产生汇报。打开的页面仍可查看最终记录；用户可暂停或关闭。关闭最后一个页面即无后续页面请求，监听进程若未 Ctrl+C 会保持空闲。长期不用时停止服务即可。

## 阅读与历史

- 沿用现有浅色布局、CSS 筛选和原生 details。自动更新保留同轮次筛选、展开项、焦点与阅读锚点；选中文字时延后替换，以免破坏复制。每次成功核对不抢焦点，连接状态使用一个完整的无障碍消息。
- 轮次选择器显示所选轮次的**当前已记录状态**与保留的历史绑定，不是穿越到过去的不可变导出；切换轮次不重新派工。
- 需要归档、发送或审计证据时，仍执行 `dashboard <state.json> <new-output-directory> [asOf] [--codex-links]`。保留整个导出目录及 `READY.json`；历史文件不自动重写、删除或清理。
- 最新页不扫描磁盘收集旧 HTML，也没有可写导出 API。既有静态 `file://.../index.html` 不会自动升级为 live 页面；应另行启动并打开最新入口。

## 安全与事实边界

HTTP 只提供固定 shell、CSS、浏览器脚本及 `/api/view`、`/api/metrics`；两个数据接口均要求随机的每进程 Bearer 凭据，并检查 Host、Origin 和 Fetch Metadata。指标只读取启动时配置的同团队 JSON，完整校验后安全渲染，不加载任意 HTML。没有 HTTP 文件路径参数、CORS、写入、导航执行、消息或定时任务 API；响应 `no-store`、禁止框架嵌入、外链脚本和外部网络来源。源读取失败返回无私有路径的错误，不回退到过期成员缓存。

这是可信本机工具，不是多用户权限系统。它不能抵御已控制同一操作系统账户、浏览器或同源历史 Service Worker 的恶意代码；不同本机服务不要长期复用同一浏览器 origin，可用 `--port 0` 降低碰撞。不要端口转发、反向代理或公开托管此服务；需要远程协作时应另行设计身份与网络隔离。

`readState` 遵守现有原子文件与投影校验契约，不写业务文件，也不为看板占用状态写锁。视图是两套记录的经校验读取，不是对所有 Agent 的全局实时事务。Node 版本不变而 Registry 成员变化也会更新视图；模型、Token、实际执行状态未采集仍显示未知。

## 开发验收

```text
node --experimental-test-isolation=none --test test/dashboard-live.test.mjs test/dashboard-client.test.mjs test/dashboard.test.mjs test/dashboard-export.test.mjs test/dashboard-navigation.test.mjs
node scripts/dashboard-live-smoke.mjs
```

第二条仅启动内存模拟团队。控制终端输入 `update` 更新任务观察，`grow` 增加长进展以检查滚动锚点，`fail` / `recover` 模拟读取失败和恢复，`reads` 查看请求读取次数，`stop` 结束。不访问真实 Registry、状态文件、任务或自动化；不能把模拟交付当作真实团队验收。
