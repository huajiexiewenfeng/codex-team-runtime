# Dashboard U3 容量与性能验收

U3 保留 v1 页面/报告、usage2 和 timeline 合同，当时统计规则为 `dashboard-stats-v2`、采集器为 `bounded-metadata-v2`。U6显式上下文归属升级使用v3规则/采集器及新cache，见 [任务归属与声明步骤](task-attribution.md)；历史U3容量/性能证据继续保留。

内部冻结任务阶段使用状态/开始/结束元组；在返回任务页或详情阶段页时恢复原字段与稳定 ID。进度时间通过一次事件索引取得。净化任务投影以无损 deflate 保存，单编码≤1 MiB，base 与任务 lease 共32项/32 MiB；解码也有32 MiB上限。先检查投影和总预算，再创建磁盘 base，失败不会留下新租约。完整任务和阶段历史不截断。

统计按任务和 binding 一次分组，替代逐任务扫描。进程内最多保存16项/16 MiB冻结结果；每次查询仍先检查磁盘租约、规则版本、查询相等及原到期。已删除或过期 lease 返回409，旧版/损坏规则失败关闭；缓存命中不能绕过验证，访问不延长快照。

切换根视图会清除隐藏表格，筛选/页码/快照状态仍保留；只有当前视图挂载记录，避免50行任务页额外保留隐藏总览行。分页按钮与每页选择具有稳定焦点键；点击首页/末页后变为禁用时，焦点移至当前页按钮。详情历史、失败父视图和输入保留仍使用 U2 缓存恢复。

容量夹具支持显式 `activityTaskCount` 和 `longNames`，默认56任务/60步骤行为不变。1000任务可以只给90任务绑定60步骤，避免为了任务规模扩大采集来源预算。生产与合成证据必须分开。

建议验收顺序：定向 API/客户端/统计测试，再适当全套 Node 测试，最后真实浏览器和只读输入哈希核对。报告每项的机器/Node、规模、测量方式、样本数、p50/p95/max、完整 HTTP 耗时、字节数、DOM行数、原始读取及 anchor 字节。冷启动首请求、已有冻结快照首次查询、缓存命中、并发和显式采集分别统计。Python进程与磁盘采集属于端到端费用，不得扣除后宣称整体达标。

U3 R1 将净化文档的去重记录和时间索引与查询结果共用原16项/16 MiB预算，以冻结来源内容、manifest、binding及缓存路径作为键，准备工作并发合并；记录引用只计一次，时间索引额外计量。每次窗口仍重新聚合，覆盖和来源时间由当前冻结租约重新绑定。时间剪裁复用数值边界，每次日聚合最多缓存10000个重复的北京日期转换，仍使用原时区函数。缓存读取不延长到期，首次准备过大时不缓存，继续有界查询。

当前1000长中文任务的 R1 验证包括20个不同团队窗口的首次查询和四客户端80个不同筛选的完整 HTTP 请求，结果与冻结 v1 逐项等价；具体 p50/p95/max 以本次交付性能文件为准。原有冷进程启动、Python状态读取及显式采集超过200ms的费用仍单独披露，不能由新窗口查询的通过推定其达标。容量通过不代表所有性能目标或全部历史覆盖通过。34.5秒有界稳定性采样及真实隐藏/暂停观察不等同于长期浸泡测试；不创建后台验收计时器。

回放只使用明确列出的来源 manifest。生产复核的74个既有获准输入不变；stateAsOf与统计源asOf分开。10月4–5日台账声明行不证明相应日期存在原生 Token/MCP，Unknown 与 sourcesPending 维持未知。
