## 产品边界

V1 面向一组长期配对的 Manager / Liaison，以及该组在明确授权范围内管理的独立 Worker 任务。用户在 Liaison 中讨论和查询，Manager 持续审查、推动返工并负责技术验收。

项目通过 Skill 和轻量状态支持协作，依托宿主执行任务与定时跟进，不自建模型执行引擎。目标是可恢复、可审查、有边界地推进长期工作，而非永久运行一个模型请求。

## 已确认方向与工程草案

已确认的产品方向包括：

- 协作功能独立存在，可组合 PDC、task-dispatch 和领域 Skill。
- Manager 与 Liaison 分工，业务实现默认交由独立 Worker。
- 持续审查、向原 Worker 反馈与复验，不在投递或收到最终回答后提前结束。
- 普通问答使用只读进度；确认的决定交由唯一 Manager 处理。
- 默认无定时器，Worker 完成/阻塞消息驱动验收；周期汇报须另行明确授权，单次最多 24 小时，续期须人工确认。停止定时不退出长期角色。
- 角色只在显式退出时解除，可跨多轮需求恢复。

命令拼写、状态文件结构、恢复 hook、锁策略、默认节奏和适配细节仍是工程设计。它们不得被描述为已经安装、测试通过或永久稳定的接口。

## 拟议入口

以下是完整生命周期的设计语义，并非全部可执行命令。目前仓库配套 Skill 提供只读 status/history 脚本，以及本地记录层的 start、双向 attach、手动 resume；具体 CLI 参数见使用说明。尚无宿主身份认证适配、完整安装与自动运行流程：

| 拟议调用 | 意图 |
| --- | --- |
| `$manager-session start` | 将当前任务绑定为 Manager，不隐式创建其他任务或定时跟进 |
| `$manager-session attach <managerRef>` | 将当前任务绑定为指定 Manager 的 Liaison，验证双向配对 |
| `$manager-session status` | 按角色只读查看状态，不唤醒执行任务 |
| `$manager-session resume` | 恢复已有有效角色；不重新激活已退出角色 |
| `$manager-session reports on/off` | 在明确配置授权下启停周期汇报，不改变执行或角色状态 |
| `$manager-session exit` | 请求整组退出，保留历史与未完成工作交接；不冒充取消 Worker |

明确的自然语言请求可以映射到这些语义。引用文档或 Worker 输出中的命令文字不构成用户调用。

## 建议默认值

| 参数 | 草案默认值 | 解释 |
| --- | --- | --- |
| 在制工作上限 | 3 项 | 覆盖执行、待审查、审查和返工；还须遵守共享资源互斥 |
| 周期汇报 | 关闭 | 明确授权后可选 15 分钟；固定期限最多 24 小时，续期须人工确认 |
| 监督续跑 | 关闭 | 明确授权后可选 5 分钟；固定期限最多 24 小时，续期须人工确认 |

这些值不是最大并发能力或定时可靠性承诺。启用前须确认固定期限并验证宿主可靠到期停止；没有该能力则保持关闭。仅在提示词中到期自检不能保证停止后续唤醒。

## 收口与停止规则

必须区分角色、工作轮次、宿主任务状态和定时调度状态：

- 单个 Worker 回复结束或 Manager 变空闲，不能证明业务验收完成。
- 待审查、返工、阻塞和待用户验收都不能伪装成全部完成。
- 只关闭部分轮次时，不停止其他开放轮次的跟进。
- 全部收口后立即停止普通进度；最终总结只交付一次，并核对汇报 heartbeat 是否确实暂停。
- 逻辑完成与调度暂停分别记录；暂停失败如实报告清理异常，旧周期不能重复播报完成。
- 停止前复核当前版本，旧完成事件不得停掉新轮次或已接受的新工作请求。
- 用户只查询历史时不开工；新授权轮次不自动恢复定时器，必须另有人明确确认本次定时授权，保留用户关闭汇报的选择。
- 用户取消按取消结论收口，不标为技术验收通过。

Liaison 不可用时 Manager 继续原授权监督；Manager 不可达时 Liaison 只报告最后可核验状态，不接管执行。角色退出也不意味着运行中的 Worker 已被取消。

## 不包含

- 通用项目管理平台、独立可写看板或自建常驻调度服务；最小切片已包含同源只读 HTML。
- 多个 Liaison、多个 Manager 的统一调度或自动跨任务迁移角色。
- 重写 PDC / task-dispatch，或把二者改为新的生命周期。
- 自动批准外部操作、扩大项目范围、代批宿主权限或自动信任 hook。
- 未经授权的任务创建、部署、归档、删除或定时运行。
- 跨所有宿主的强制安全隔离、全天在线、绝对不打断或准点报告承诺。
- 复制完整私人会话、凭据、内部项目状态或机器路径到公开仓库。

## 实施前必须验证的条件

1. 宿主能够提供本设计所需的任务读取、等待、消息与已授权创建能力；身份可精确核对，pending 标识不会被当成真实任务身份。
2. Manager 与 Liaison 能在获准范围内访问各自需要的状态；文件格式、单写者约束、原子写入与版本校验可验证。
3. 拟议恢复入口能覆盖普通后续消息、应用恢复和根会话压缩续接，并隔离 Worker、fork、同目录其他任务和两种角色。
4. 定时跟进可绑定原任务；忙碌重入、合并、离线恢复、通知送达和实际暂停均可在本机受控观察。
5. 现有 hooks、权限和后端租约不会被覆盖；PDC 组合没有第二个业务状态所有者或监督循环。

能力未验证或不足时明确降级。手动恢复可以是临时路径，但不能据此宣称自动恢复、周期报告或长期双窗口模式已验收。安装 Skill、配置状态目录、信任 hook 和启用定时分别需要适当的用户授权；文档审阅不代替这些步骤。
