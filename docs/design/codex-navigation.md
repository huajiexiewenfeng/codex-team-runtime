# Codex 对话兼容入口核对

日期：2026-09-08。结论：已确认当前安装包存在按线程 ID 导航的解析路径，用户现已确认最新验收包的成员入口能打开正确对话。该结论限于当前使用环境，仍不是严格 host/thread 导航的公开稳定契约。

## 已取得的证据

- 本机 Windows 安装包 `OpenAI.Codex 26.901.6511.0` 的 AppxManifest 声明 `codex` 协议。仅注册协议不能证明具体页面可打开。
- 只读检查包内 `app.asar`，没有执行或修改应用代码。`.vite/build/window-all-closed-KNH8jchn.js` 的 URI 路由包含 `threads` 分支；共享 `src-VqXTPopo.js` 将线程路径解析为 conversationId。
- 主进程 `main-DpnWwRdP.js` 的导航处理先读取线程，再进入其对话页面；没有提示词参数的 URI 不会填入任务文本。
- URI 解析不读取 hostId 查询参数。主进程按当前目录中的线程 ID 查找主机，存在回退路径；不能将 `?hostId=...` 声称为严格定位或权限保证。
- 所查官方 Features / Projects 文档没有给出此 URI 的对外契约；以上结论来自本机该安装版本的静态实现，不是官方跨版本承诺。

没有读取私人对话日志、修改注册表、触发应用深链接、使用浏览器或绕过本地 HTML 访问策略。上述静态证据不能代替操作系统协议唤起和落到正确会话的实测。

## 当前实现

`dashboard ... [--codex-links]` 提供显式、默认关闭的呈现选项。只有全部来源种类为 manual / host-observation，成员已 bound 到 local，且线程 ID 为规范 UUID 时，才输出普通 `codex://threads/{threadId}` 链接；没有脚本、自动点击、prompt、hostId 参数或导航工具调用。

模拟或未知来源、远程成员、pending ID、missing 绑定、异常 ID 保持禁用并说明原因。历史页按该轮次保留的成员身份生成链接。角色退出不抹掉历史对话入口；查看对话不代表恢复任务。

页面的公共可展开说明明确提示“客户端按线程 ID 定位，不保证锁定主机；浏览器唤起尚未验收”，折叠标题也保留不保证锁定主机的限制。每个入口保留本机兼容入口与核对身份的短说明，并通过 `aria-describedby` 关联公共说明，避免重复长段文字占满侧栏。点击应由人工发起，并核对成员身份。它不是已经完成的严格宿主导航；若原线程迁移、ID 在多个主机存在、浏览器不支持或客户端未安装，必须保留未知，不能推断已打开。

renderOptions 进入导出清单，但不改写业务状态、快照里的 `navigation.available`、角色或汇报状态。未启用该选项的输出保持原来的禁用行为。

## 验收证据与边界

自动测试覆盖显式开启 / 默认关闭、身份与来源拒绝、参数拒绝、历史绑定、同源重现、无脚本 / 提示词以及源文件不变。这些测试从不实际调用协议。

用户先提供优化前验收包的两张桌面截图，之后针对最新 `team-runtime-dashboard-layout-20260908` 的窄屏、筛选 / 展开 / 键盘、成员正确跳转三项检查答复“都正常”。这是用户报告的当前环境跳转成功，不是 Agent 执行协议的证据。没有逐个成员、主机或浏览器版本日志，不外推跨主机保证。新增测试检查公共说明只出现一次、各入口仍有对应的完整可访问性描述，未改变 URI 或身份拒绝规则。

以下保留导航检查方法，迁移环境或更新客户端后仍须重新核对：

1. 打开专用已完成测试团队的 HTML，检查桌面、窄屏、筛选、展开与键盘焦点。
2. 点击其中一位测试成员的兼容入口，确认浏览器是否提示打开客户端，以及是否落到准确线程。
3. 核对主机、线程 ID 与成员名称；不要发送消息或重启任务来验证导航。
4. 记录客户端版本和实际结果。未通过时保留默认关闭，不以静态解析或测试通过代替实测。

当前环境的人工点击验收已取得；严格跨主机锁定仍不具备，不能将成功打开本机对话理解为该能力已实现。默认关闭、显式 opt-in 和身份拒绝规则保持不变。已验收 HTML 是固定导出，原有“尚未验收”提示作为导出时说明保留，本次确认记在文档中，没有改写该包或为其他环境预先赋予成功状态。
