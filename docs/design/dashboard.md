# 团队只读工作台

状态：2026-09-08 已根据用户桌面截图修正摘要与说明层级；最新本机版本已获用户人工验收确认。沿用已确认的浅色工作台草图，由 ui-ux-pro-max 辅助统一信息层级、可访问性与视觉规范。证据及未覆盖的环境组合见 [验收记录](../dashboard-validation.md)。

## 设计依据

本地检索 `developer analytics dashboard` 命中 Data-Dense Dashboard：蓝色数据、琥珀色关注项、紧凑网格、等宽数字。检索附带的 Enterprise Gateway 营销落地页结构不适用，未采用；首次 `team operations dashboard` 的体育红色主题也未采用。

采用灰白背景、白色卡片、蓝色导航、绿色验收、琥珀色阻塞。使用本地 Segoe UI / Microsoft YaHei 与 Consolas 字体，不请求外部字体或引入前端框架。视觉来源是已有草图，非营销主页模板。

## 信息架构

- 左侧锚点导航：概览、交付、成员、动态；窄屏变为顶部导航。
- 顶部：明确快照来源、轮次范围；总览以总轮次 / 开放 / 关闭数量概括，不拼接全部历史标题；已验收 / 执行与返工 / 审查 / 阻塞四项计数。
- 轮次入口：可展开导航切换全部轮次 / 指定历史轮次，以 `aria-current` 标记当前页；轮次历时单列，不把并行轮次相加成模型工时。
- 主区：阻塞原因、六类任务筛选、任务卡片、原生可展开详情、审计动态、完成摘要。
- 侧栏：Manager / Liaison / Worker 角色、任务归属、任务历时、绑定身份、汇报状态与未采集的成本说明。
- 页尾：固定 asOf、源版本、快照摘要 ID、UTC 时间语义。

任务卡摘要按业务状态呈现：已验收优先显示验收结论、验收时间与冻结历时，不再把缺少进展观察写成尚无进展，也不显示仍在推进的当前阶段。排队显示尚未执行和排队已等待；取消显示取消原因、排队等待与未执行 / 未验收。原始观察、阶段与验收证据保留在详情中。任务全部收口时，不显示零项陈旧观察警告。

成员入口采用渐进展示：公共兼容限制只在团队栏显示一次，折叠标题保留不保证锁定主机的提示；每个入口保留本机兼容入口与核对身份的短说明，并通过 `aria-describedby` 关联完整说明。此次检索未命中合适的折叠规则，采用 ui-ux-pro-max 内置渐进展示与信息层级原则，没有引入新主题。

长团队名称：业务允许最多 4000 字符，标题容器显式允许收缩、限制最大宽度并使用 `overflow-wrap:anywhere`，保留完整名称。ui-ux-pro-max 的 Web / Long Token Wrapping 检索支持这一处理。回归检查验证完整转义文本与输出 CSS 边界，不宣称测得实际浏览器几何或已完成窄屏验收。

## 正确性与边界

离线导出的 HTML 从同一个不可变 snapshot 派生。筛选采用原生 radio 与 CSS，详情采用 details，不运行页面脚本，不读取其他状态文件，不发送消息、不派单、不创建定时器、不自动刷新。

派发结果和执行状态分开；领取记录不等于实际调用次数。历时包含等待，完成后冻结；未知时间、用量不显示为 0。阻塞不自动解释成必须由用户决策。历史身份以所选轮次为准；跨轮汇总明确可能含旧绑定记录。

成员任务链接只定位本页记录；定位任务不受当前筛选限制并有文字说明。Codex 对话入口默认禁用。显式 `--codex-links` 可为非模拟、本机、已绑定且 threadId 有效的成员显示兼容链接；链接仅交由客户端按线程 ID 查找，不能保证锁定主机。当前环境的正确跳转已有用户确认，其他环境仍须核对。绑定身份可展开并手动选中复制；不能把 Agent 工具当作网页 API。具体证据及限制见 [导航核对记录](codex-navigation.md)。

`dashboard` 命令一次导出总览与各轮次页面，支持页面内切换历史。各页面用同一份内存状态和同一个 asOf，历史页保留轮次成员绑定；轮次计时到关闭时间后冻结。导航只包含导出目录内的生成文件名，不使用用户提供的轮次 ID 作为路径。`READY.json` 在全部页面写入后生成，包含各页快照 ID、文件 SHA-256 摘要；缺少该标记即导出未完成。已有目录拒绝覆盖。

旧 `snapshot` / `render` 命令保留单页导出。模型 / Token 采集、可写控制和长列表 / 全量历史虚拟化不属于此版。

## 2026-09-11：最新工作台

在既有静态导出旁增加 `dashboard-serve` 本机只读入口，不改变已验收的视觉主题。浏览器可见时每 5 秒请求当前 Node + Registry 投影，隐藏 / 暂停 / 关闭后停止请求；服务无后台扫描、Agent 唤醒或自动化。历史导出不自动覆盖，轮次选择不是过去时间点的归档。具体维护分工、凭据、安全边界和命令见 [最新工作台说明](../live-dashboard.md)。

ui-ux-pro-max 的 `live status screen reader` 检索命中 Contextual Live Badge Updates：采用一个完整、原子的连接状态消息，不移动焦点或让多个数字同时播报。复用本地字体与现有 CSS；新增可暂停、可手动刷新、带标签的原生轮次选择器。断连保留已显示数据并说明不是最新，成功核对时间与业务观察时间分开。刷新保留筛选、展开、焦点与主要区块阅读锚点，选中文字时延后替换。

## 验收

自动测试检查计数、筛选结构、空状态、派发证据、转义、确定性与不变性。静态审查补齐了排队任务的未收口计数，以及不受最近 12 条动态限制的完整派发审计证据。

用户提供了优化前 v40 兼容入口验收包的两张桌面截图，证明其中总览、任务卡和成员入口已呈现；截图暴露的终态摘要与重复长说明已据此调整。截图不是优化版视觉证据，也不能确定 CSS 视口 / 缩放值或证明交互成功。

2026-09-07 内置浏览器 URL 安全策略阻止 Agent 导航本地 HTML，未绕过限制。用户在最新 `team-runtime-dashboard-layout-20260908` 交付后，对缩窄窗口、筛选 / 展开 / 键盘操作、成员正确跳转的检查统一答复“都正常”。据此记录当前环境人工验收通过；不宣称获得逐尺寸、缩放或跨浏览器专项测量。保留用户验收的原包和旧包，不在收尾时修改页面。

持续保留零外部依赖与严格 CSP。CSS 筛选使用 `:has()`，目标为支持该选择器的现代 Codex Chromium；旧浏览器的筛选兼容性不在此版验收范围。兼容链接沿用同一蓝色语义与可见焦点，点击目标至少 44 CSS px 高；不会在加载页面时自动跳转。
