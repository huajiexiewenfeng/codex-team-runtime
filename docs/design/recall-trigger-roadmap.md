# 角色召回触发：后续计划与边界

- 更新日期：2026-09-12。
- 状态：MCP 工具描述提示已在源码补充并本地安装；新进程工具目录验证通过，已有 MCP 连接需重启加载。未启用宿主自动触发，实际召回率待评估。
- 当前决定：暂不加入 Hook。压缩后由宿主自动召回保留为后续研究项，不再作为下一版 P0 必做项。

## 当前能力

`team_context.read(host_id, thread_id)` 由调用方显式发起，返回对应任务的角色、团队、Leader 和职责。Python 服务的这个入口没有 compact 事件参数，也没有订阅宿主压缩事件。

服务持续连接不等于持续收到任务上下文。仅在服务内增加 `if compact`，既不会让入口自行执行，也不能证明当前任务刚发生压缩。MCP 连接身份不能代替原生任务身份。

现有关键节点召回契约继续有效，见 [共同 Team Context 契约](../../skills/manager-session/references/team-context.md)。不因本次讨论删除交付、接收、验收前的身份检查。

## 路线一：MCP 入口描述提示，已补充源码

用户已确认“入口”指 MCP 工具描述，目标是提高召回率而非接入系统压缩事件。`team_context.read` 的描述现在明确要求：继续团队工作时，若经历上下文压缩或角色上下文丢失，先调用工具恢复身份、团队、Leader 和职责；适用于 Manager、Liaison、Worker。

- 这是模型可见的调用提示，不是确定性的事件处理器；仅修改服务源码中的工具描述，参数、返回格式和登记逻辑不变。
- 只有 Agent 实际调用后，Python 才能确定性匹配身份并读取 Registry。
- 不能承诺每次压缩都会调用，也不能把工具可发现性或单次成功当成召回率验证。
- 应限制提示长度；全局工具目录可能让无关任务看到描述，不能承诺零 Prompt 开销。
- 未登记身份返回 null；不自注册、不推断角色、不改变团队和在途工作。
- 单纯新增 `reason=compact` 参数也不会制造事件来源；调用方声明不构成宿主事件证明。

沿用真实 stdio 回归测试检查工具目录中的提示、精确身份边界、null 行为和原有生命周期。元数据测试不证明模型召回率提高；后续用已授权的真实任务观察压缩续接时是否调用、角色恢复是否正确及无关任务误触发情况。全局安装和 MCP 连接加载状态需另行核对，不把仓库源码改动说成当前连接已经更新。

## 路线二：宿主事件自动召回，暂缓

目标是压缩后、下一次模型请求前，由宿主发起只读查询并把精简角色上下文交还同一任务，不依赖模型自主选择调用。

官方文档给出了 `SessionStart` 匹配 `compact` 的上下文注入时机，并支持 Hook 直接调用已连接的 MCP。该能力是后续接入依据，不代表本项目已经接入或本机端到端验证通过。[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks#sessionstart)

若未来恢复此路线，需单独确认并验证：

- 精确宿主/任务身份映射，以及 Manager、Liaison、Worker、临时子 Agent、fork 和无关任务隔离。
- 只注入有界的角色与工作入口，不复制完整历史；未登记任务不注入团队上下文，退出角色不自动恢复。
- 手动与自动压缩后都能在同一任务立即续接，不仅是后台读取成功。
- Hook 输出契约适配、用户信任、安装兼容、超时和 MCP 未连接时的能力缺口。
- 不覆盖既有 Hook，不绕过信任，不新增默认定时器或 LLM 轮询。

没有宿主事件输入或其他经验证的接入机制时，不宣称 MCP 服务能够自行检测压缩。若未来出现非 Hook 的宿主接口，再独立评估；不以监听私人会话日志、常驻扫描或新的监控服务替代当前已暂缓的路线。

## 与下一版效率优化的关系

继续讨论有界 Token 归因审计、精简决策视图、无待处理事项时结束回合，以及带版本和证据的工作检查点。保持模型配置、身份与验收门禁不变；具体实施范围由后续确认和证据决定。

将“提醒 Agent 召回”“服务确定性返回”“宿主自动触发并注入”分别记录和验证，不把三者合并成一个已完成的长期记忆能力。
