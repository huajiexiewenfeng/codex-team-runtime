# Team RSI：基于运行证据的受控持续改进

日期：2026-09-19。状态：用户已确认方向；本文件定义设计与首轮路线，不代表已部署自动改进系统。

## 定位

RSI 在本项目指团队对自身 Skill、运行流程与工具接口的持续改进，不指模型权重训练，也不是无限递归自治。

北极星见 [NORTHSTAR](../../NORTHSTAR.md)。团队不只执行任务，还要能够基于真实运行证据发现重复问题、提出假设、试用修改并证明是否改善。当前先内部实现，不依赖外部 Trace/Eval Runtime；未来适配不能成为当前采集和交付的前提。

## 最小闭环

真实任务 → Trace → Metrics → 半自动 Eval → 改进候选 → 单项试用 → 对比验证 → 保留 / 回退 / 继续观察。

| 层 | 职责 | 产出 | 不能做 |
| --- | --- | --- | --- |
| Trace | 保存指定任务的可追溯运行元数据 | 角色、任务、消息、工具、状态与时间线 | 复制隐藏推理；无授权扫描其他会话；猜测缺失事件 |
| Metrics | 确定性计算已观察成本、质量与覆盖 | 阶段历时、Token、调用/通知/返工次数、缺口 | 把空档等同推理、重复等同浪费、缺失等同零 |
| Eval | 判断候选问题、可比性和验证方法 | 有来源的事实、假设、反例、目标指标、修改建议 | 自报效果当验收；生成无授权执行指令；随意降低标准 |
| Loop | 在已授权范围执行一个可回退试验 | 版本差异、试用范围、样本、结果与决定 | 默认自行修改生产、自动扩散全团队或无限尝试 |

Trace 与 Metrics 是事实基础，Eval 的判断是带证据的建议，不写回或改写原始事实。业务 state/Registry 继续拥有任务和成员权威；RSI 不建立第二个调度器。

## 半自动 Eval 的固定输出

每个候选至少回答下面六项，使用引用而不是大段复制日志：

1. **事实**：哪几个任务、事件 ID、工具结果支持问题；哪些数据缺失。
2. **假设**：拟解释什么，哪些其他解释仍未排除；不能直接从耗时猜模型内部原因。
3. **目标**：主指标与质量护栏；改进成本如何记录。
4. **单一差异**：改什么、明确不改什么；归属 Skill / Runtime / 环境 / 无需修改。
5. **验证**：已有失败样本回归、反例、后续可比真实任务；通过/失败/证据不足如何判定。
6. **处置建议**：试用、暂缓或不修改；需要哪些现有授权之外的用户决定。

确定性代码计算指标、检查数据一致性；Agent 分析候选并生成可审查差异；用户确认重要取舍和有限试用范围。修改者的自评不能替代实际测试或既定独立验收。无需为此默认创建新的评估 Agent 或团队。

一次明确的有限试用授权可以覆盖实施、指定范围安装、验证和约定回退，不为每个机械步骤重复制造审批材料。扩大范围、改变权限/模型或提高风险时重新确认。批准一份候选说明不等于批准无限生产自修改。

## 允许改什么

- **Skill**：角色边界、决策条件、流程指导、冗余规则；删除规则也是改进。
- **Runtime**：确定性机械步骤、高层接口、结果投影；不把底层状态机的全部细节留给 LLM 每轮编排。
- **工具/环境**：命令组合、构建依赖等有独立证据的问题；按各自授权处理，不冒充 Skill 修复。
- **不修改**：必要开销、缺证据、混杂过多或预计收益不抵维护成本。

观测缺口先修测量，测量变更与业务行为变更分开记录。不要因为 RSI 存在就要求每次完成任务必须反思、再多发一条消息或更新一份长报告。

## 实验生命周期

候选 → 待授权 → 回归验证 → 有限试用 → 观察 → 保留 / 回退 / 证据不足。

这是待实现的管理契约，不是已经存在的 Runtime 状态机。当前用 [单变量优化台账](../optimization/team-flow-experiments.md) 人工维护，所有阶段都保留历史。

- 一个评估范围同时仅有一个活动的行为实验；其余候选等待，不叠加。
- 每项保存基线、patch/文件哈希、实际安装与加载版本、范围、起止时间、样本和决定。生成报告的版本不是历史执行版本。
- 在途任务保持明确版本；规则更新边界需记录。不能假定磁盘覆盖后所有 Agent 立刻换用新规则。
- 第一次观察窗口 1–2 天、至少 3 个可比任务是初步检查点，不是统计显著性保证；不够样本则继续观察，不自动宣布成功。
- 保留失败样本并分任务类型，跨日/并行不重复算；主动标注模型、输入规模、缓存、网络或验收标准变化。
- 需要回退时只还原该实验差异，先检查在途依赖；不重写历史、不删制品、不清空 Registry、不强制中断 Worker。
- 没有新证据就不重新评估同一问题。默认按用户请求或获准的阶段复盘执行，不增加定时器或常驻 Agent。

## Eval 的回归与防退化

每次真实失败保留最小、脱敏、可重放的案例与预期行为；同一缺陷必须有原失败样本和至少一个反例。后续真实试用使用新样本，不能只在用于修改规则的旧案例上宣布有效。

例如 E01“成功通知后不轮询 Manager”：

| 场景 | 预期 |
| --- | --- |
| 提交与精确通知结果均成功，工作结束 | Worker 可结束本轮，保持待审/占用 |
| 通知结果未知或被拒绝 | 保留恢复/拒绝状态，不伪造成功、不绕过拒绝 |
| 用户明确要求本轮继续等待 | 依明确授权处理，不套用默认快速结束 |
| 已提交但 Manager 未通过 | 不擅自接下一项任务、不自行批准 |

速度与成本改善不能通过取消汇报、遗漏验证或降低验收质量获得。统计时同时报告业务成本与采集、分析、修改、回归和维护成本；无法精确归属的成本单列未知，不掩盖。

## 工作台中的 RSI 信息

沿用任务时间线与指标页，增加实验 ID、当前状态、基线/试用样本及结论入口；不建立第三个独立 Dashboard。展示“候选”和“生效”区别，缺少加载证据就标未确认，数据刷新不等于开始实验。

## 非目标与权限边界

不训练或修改基础模型，不自动修改宿主安全策略，不伪造人工批准，不以评估为由读取未授权任务，不做模型/团队自动扩张，不默认接外部平台，不自动提交推送。RSI 文档和观测数据不能授予自身新的执行权限。

这个闭环的成果是可验证的改进与积累的回归案例，不是改动次数、复盘字数或更多 Agent 消耗。
